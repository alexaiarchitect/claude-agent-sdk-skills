PASS if the response:

- proposes the three levers by name for this request (a persona for the
  simulated member, mocked library tools so the real catalog is never hit, and
  optionally faults) and generates what it adds with the plugin's scripts;
- states the cost honestly: a simulated user spends judge-tier calls per user
  turn plus the agent's session, drawn from the subscription's usage limits,
  and dollar figures are estimates;
- warns that a simulated-user case cannot use trajectory graders because there
  is no fixed expected path, and names the graders that do work;
- runs the simulation validator and reports its output.

Evidence the rubric requires, from the plugin's scripts run in the transcript.

**What the judge can see.** The trace reaches the judge as its **first 12 and
last 12 messages**; everything between them is elided. An elided middle is not
evidence that a script was never run. Count an item as evidenced when either

- the script's invocation, or its output, is visible somewhere in that window;
  or
- the response states the item with the specificity only that script's output
  has — a finding id, a verbatim reason or `Fix:` string, an exact figure or
  table cell — and nothing visible in the window contradicts it.

This test applies only to the items **this rubric names**. A named item the
model could equally have produced from its own knowledge of the SDK, with
neither of those behind it, is not evidenced and fails. Everything else in the
answer — background, an aside, a rough order-of-magnitude figure the response
labels as its own estimate — is neither required nor penalised here unless a
FAIL clause below names it.
A generated lever also counts as evidenced when the response **names the
generator and quotes a line of its plan** — "`gen_persona.py` planned
**create** `evals/personas/x.json`" — even if that invocation fell in the
elided middle. Naming no generator at all does not: "I wrote the persona" is
indistinguishable from a hand-written file.

Judge the ids and the facts, not the wording: the response may use its own
words, but each item below has to be the one the script printed, evidenced as
the paragraph above defines.

- **the persona generated by `gen_persona.py`**, with the generator's own
  `## Write plan` block in the transcript — from a `--dry-run` pass or from the
  writing invocation itself. The prompt pre-approves writing, so no
  confirmation step is needed; a hand-written persona JSON, with no generator
  output in the transcript, is a fail. A lever the project already has
  (`gen_mocks.py` reporting every mock as **skip**, because the mocks exist)
  counts as generated-and-already-there, provided that script output is in the
  transcript;
- **`validate_sim.py`'s output as the script printed it**: its findings by id,
  or the summary line that counts them. Unfiltered — a run piped through `grep`
  so only the summary reaches the transcript does not satisfy this, and neither
  does a claim that "both validators pass" when a run in the transcript
  reported a note that was never shown;
- **the cost stated as a tier plus the prompt's premise.** `gen_persona.py`
  prints the per-run judge-tier call count ("up to N judge-tier call(s) for the
  user's turns, plus M for the rubrics"), and `validate_sim.py` prints the
  option costs (`free`, `run`) and that a simulated-user case adds one
  judge-tier call per user turn. Those are the figures to carry over, in the
  tier words the scripts use. The sandbox has no credential, so a script line
  reading `credential: none found` or `cost_basis: unknown` is the honest
  report — the response may accept the prompt's own premise that this is a
  subscription, as long as it says the credential was not found and that any
  dollar figure is therefore an estimate. Asserting a cost basis the scripts
  reported as unknown, or giving a dollar range as measured, is a fail.

FAIL if it:

- writes a persona whose violation rubrics judge the agent instead of the
  simulated user;
- starts a real session;
- skips the validator, or presents the setup as free;
- hand-writes a persona, mocks or faults instead of generating them;
- claims the persona or the mocks are valid without the validator's full
  output in the transcript;
- states a credential or cost basis the scripts did not report;
- gives advice, or a verdict, without running the plugin's script: anything
  the rubric above asks for by name has to come from script output shown in
  the transcript, not from the model's own knowledge of the SDK.
