# Run Agent SDK evaluations

Every run spends: one SDK session per case per run, plus a judge call per
`llm` grader per sample. On a subscription that spend is plan quota and the
SDK's dollar figure is an estimate; on an API key it is the bill. So nothing
here starts a session before the user has seen the command, the credential and
the arithmetic, and afterwards the verdict comes from the result files, not the
terminal scroll.

`${CLAUDE_SKILL_DIR}` is this skill's directory.

## Flow

1. **Discover.** Runner copy, interpreter, credential, cases:

   ```bash
   python3 ${CLAUDE_SKILL_DIR}/scripts/check_runner.py <project>
   python3 ${CLAUDE_SKILL_DIR}/scripts/run_evals.py <project> --tier pr --dry-run
   ```

   `--dry-run` prints the exact command, the credential kind, the results
   directory and a `sessions_total:` line, and starts nothing. Add `--json` for
   the per-case `runs` and `runs_source` behind that total.

2. **Report.** The runner copy version against the plugin's, the interpreter
   and SDK version, the credential line verbatim, the tier's graders, and how
   many sessions will start. Quote the dry run's own lines rather than
   re-deriving them: **`sessions_total`** is the session count (never recount
   the cases by hand), and the `interpreter:` line carries its own
   qualification — `(unverified - claude_agent_sdk not checked)` means the dry
   run did not probe the SDK, so say that it was not verified rather than
   asserting a version either way. `check_runner.py`'s probe line is the other
   half: report its result as it is worded.

3. **Options and cost.** Say the arithmetic: cases × runs sessions, plus
   `llm` graders × samples × runs judge calls. Offer the `pr` tier (free
   graders, one run) before `nightly` (judges, repeated runs), each with its
   cost tier and its own numbers — dry-run the other tier too rather than
   guessing what it would add, or read its `runs` and `graders` from the
   config's tier block and say that is where they came from. On a
   subscription, mention that a usage limit mid-suite marks the rest
   `NOT_EVALUATED` and exits 3, never a fake failure.

4. **Confirm, run, hand off.** Then send the results directory to
   `/agent-sdk:eval-analyze`.

## The honest gates

| Route | Gate | Use it |
|---|---|---|
| `scripts/run_evals.py` | exit code from the result directory | anywhere a result must gate something |
| `python -m agent_sdk_evals run` from `evals/runner` | the runner's own code | CI steps generated by `/agent-sdk:eval-ci` |
| `tests/test_evals.py` (pytest) | pytest's code; the gate asserts on the aggregate | projects that already run pytest |
| `scripts/replay_trace.py` | free graders over a saved trace | "would the last run still pass" after a grader change |

## Decision rules

- **Refuse a missing or newer runner copy.** `DEP003` means nothing can run;
  `DEP002` means the copy may write result files this plugin cannot read.
  An older copy (`DEP001`) runs, with a warning to upgrade.
- **Never inherit the CLI's default model.** The runner refuses a run with no
  model from the case, the config or the agent; the default on this account
  measured four times Sonnet's cost.
- **Repeat runs with `--runs N`.** Each run is kept separate so
  `/agent-sdk:eval-analyze` can compute pass@k; nothing is averaged.
- **`NOT_EVALUATED` is not a regression.** Default `--not-evaluated warn`
  locally (exit 3 means inconclusive); use `fail` in CI, where a suite that
  silently stops scoring is worse than one that fails.
- **Only a `rejected` rate-limit status stops a suite.** Warnings are recorded
  and the run continues; the aggregate carries the last status and the reset
  time. `--wait-for-reset` sleeps until the reset once and retries what is
  pending.
- **Concurrency stays at 1 unless asked.** Every session is a full CLI child on
  the same credential.
- **Run the cheap tier first.** There is no point paying a judge to score an
  agent that called the wrong tool.
- **Isolation is on unless a case turns it off.** `setting_sources=[]` and
  `strict_mcp_config=True` are forced by the runner; a case that overrides them
  measures the developer's machine, and the trace says so.

## Scripts

| Command | Does | Exit codes |
|---|---|---|
| `scripts/run_evals.py <project> [--tier T] [--runs N] [--case G] [--tag T] [--max-cost-usd X] [--concurrency N] [--wait-for-reset] [--not-evaluated fail\|warn] [--dry-run] [--json]` | runs a tier through the runner copy and gates on the result directory | 0 passed, 1 failures, 2 environment, 3 inconclusive |
| `scripts/check_runner.py <project> [--json] [--no-probe]` | runner copy version and manifest against the plugin; asks the copy for `version` | 0 up to date, 1 older or modified, 2 missing, newer, or not importable |
| `scripts/replay_trace.py <project> <trace> [--case-dir D] [--judge] [--json]` | re-grades a saved trace with the free graders | 0 passed, 1 failed, 2 environment, 3 never evaluated |

## Completion checklist

- [ ] The runner copy version, interpreter and SDK version were reported, not assumed.
- [ ] The credential and its cost basis were stated before anything started.
- [ ] The session and judge-call arithmetic was stated before the user chose.
- [ ] Failures and never-evaluated runs were reported separately.
- [ ] The results directory was named and handed to `/agent-sdk:eval-analyze`.
